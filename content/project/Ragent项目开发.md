消息队列（MQ message queue）
什么是消息队列？
可以把 消息队列想象成“排队的邮箱”或者“传送带”：
生产者（Producer）：把消息放到队列里，就像把信件投到邮箱里。 
队列（Queue）：信箱或者传送带，负责存放消息，按顺序传递。 
消费者（Consumer）：从队列里取消息去处理，就像邮递员把信送到收件人手上。 
关键点：生产者不用管消费者什么时候处理消息，只管放消息进去就行。

 为什么要用消息队列？
异步处理 → 不用等太久
 类比：你去快餐店点餐，厨师慢慢做菜，你先去找座位，不用站在柜台等。 
 软件场景：用户下单 → 消息队列 → 后台系统慢慢处理（库存、发货、发短信），用户界面响应快。 
解耦 → 模块独立
 类比：快递公司、仓库和商店分开，商店不需要知道快递的内部流程，只负责把包裹放到传送带上。 
 软件场景：订单系统不需要关心发货系统怎么实现，只要把订单消息放进队列就行。 
削峰 → 防止系统被压垮
 类比：地铁高峰期，人太多直接挤不进车站，车站开一个“排队通道”，让大家慢慢进入。 
 软件场景：秒杀活动瞬间下单量巨大 → 消息队列排队 → 系统慢慢处理订单，避免崩溃。 
保证可靠 → 不丢东西
 类比：信件投到邮箱里不会丢，邮递员会按顺序送达。 
 软件场景：支付成功消息、用户通知消息通过 MQ，确保不会丢失
消息队列里的消息可以是 请求、请求的结果或事件通知，它的核心作用是 在模块之间传递信息，让系统异步、可靠、解耦。
RustFS
一个用 Rust 语言 写的文件系统（file system）开发框架。 
作用：帮你快速搭建 高性能、可靠、可扩展的文件存储系统。 
适合场景： 
 分布式存储（类似 S3） 
 网络文件系统 
 高并发读写、缓存系统 
优势： 
 Rust 内存安全，不容易出错 
 支持并发处理，性能好 
 易于扩展和自定义存储逻辑 

简单说：

RustFS 就是一个“搭建文件存储系统的工具箱”，你不用写复杂底层代码，就能做高性能的文件存储服务。
Docker Image
在 Docker 中，image（镜像） 是一个只读的模板，用来创建容器。可以把它理解成一个 程序的“安装包”或快照，里面包含了程序运行所需的所有东西：
操作系统环境（比如 Ubuntu、Alpine 等） 
程序本身（比如 RustFS） 
依赖库和工具（程序运行所需要的库、语言运行时等） 
配置文件和默认设置
当你运行命令：
docker run rustfs/rustfs:latest
rustfs/rustfs:latest 就是 Docker image 
 Docker 会根据这个镜像创建一个 容器（container），容器是镜像的 可运行实例
 你可以启动、停止、删除容器，而镜像本身不会变 
🔹 类比：
 镜像 = 软件安装包（可以复制多份） 
 容器 = 安装后运行的软件实例
